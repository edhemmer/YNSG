# YNSG Production activation steps — October 10, 2026

The .app portal was restored to verified release 7ae9900 using Preview configuration after Production settings and readiness checks failed. Settings version 5 now contains the owner-approved completion payment terms. Do not declare the Production environment accepted until the following checks succeed.

1. In Vercel, open project ynsg-repo → Settings → Environment Variables. Compare existing Preview and Production scopes for APP_ORIGIN, SUPABASE_URL, SUPABASE_PUBLISHABLE_KEY and SUPABASE_SERVICE_ROLE_KEY. Production APP_ORIGIN must be https://yourneighborhoodserviceguy.app. Use the same correct YNSG Supabase project. Preserve secrets; do not send values through chat. The connected tools cannot inspect or update these Production settings (HTTP403), so the exact difference has not been verified.
2. Verify Google consent/token and worker variables also have the intended Production scope. Preserve the existing GOOGLE_TOKEN_ENCRYPTION_KEY; replacing it can invalidate stored account tokens. Retain the registered worker credentials and calendar/mail worker configuration. A configured variable alone is not proof of working delivery.
3. Redeploy the reviewed CRM source in Production. Before changing the live apex domain, check owner settings publication, scheduling readiness, calendar confirmation, Gmail delivery, sample suite loading and card connection on that deployment. If any fail, retain the restored live deployment and inspect actual server errors.
4. After acceptance succeeds, Settings → Domains → edit yourneighborhoodserviceguy.app → connect to Production instead of the codex/crm-workflow Preview branch. Check both apex and www aliases and source/environment. A manual alias can be overwritten by the next branch build while the branch assignment remains.
5. Verify actual Stripe live merchant mapping, server-only STRIPE_SECRET_KEY and the real production STRIPE_WEBHOOK_SECRET. The webhook endpoint is /api/stripe/webhook. Complete a separately authorized actual card payment, signed webhook, receipt and settlement reconciliation. No sample email counts as collected money.
6. Review seller details and the applicable service/location tax treatment before issuing a real invoice. Tax is still unreviewed; do not select non-taxable simply to unblock invoicing. Confirm real inbox/phone receipt for the 15 accepted email samples and real customer access to the invoice.

Automatic franchise provisioning, territory enforcement and local website/catalog synchronization remain engineering work. The review documents do not certify them as implemented.
