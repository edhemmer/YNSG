# Owner network and connected field support — October 30

Requested directory: private owner/admin phone book for contractors and other referral contacts, searchable by name/category, with multiple categories per contact, business-card photos, phone/email/web/social links, private notes and a meaningful vetting badge. This directory is separate from customers and from YNSG’s offered service catalog.

Executable contracts are defined first in `apps/web/lib/owner-network-contract.ts`. Names/contact methods/social links/categories/notes are bounded; links permit only HTTP(S) without embedded credentials. List results have 20-record pages and at most 500 category filters; searches also match category names so categories beyond that filter page remain discoverable. Contact detail and card reads remain tenant/actor bound.

Vetting has three explicit states: not vetted, referred to the owner, and firsthand known work. Only the owner can establish or revise firsthand vetting; it needs an explicit attestation and a description of the work known. Identity or category changes require a renewed owner review to retain the badge. A business-card photograph or AI suggestion never establishes vetting. This is an owner’s experience record, not a claim of independent certification. Record review date/actor and retain vetting changes privately.

Canonical commands require current company permission, exact revision and actor-bound idempotency. Mutations are serialized per company. Private contact/category/link tables have RLS and no client table grants; public invoker wrappers call narrow guarded private functions. Archiving is reversible and retains evidence. No real contacts or reviews are seeded for QA.

Recovery persists only a pending operation’s company/actor/contact IDs, key, revision and payload hash in browser storage, not the private contact payload. An in-memory retry resends the identical body. After reload, an explicit reconciliation command checks the actor/key receipt under the same lock; if no mutation committed, it records a not-applied tombstone so a late original request cannot apply afterward. All other contact writes remain frozen until resolution.

Business-card reference photos use the existing private attachment bucket and JPEG/PNG byte-verification approach, with separate owner-network metadata/permissions. No fake customer is created. Uploads deduplicate the same image within a contact, cannot replace stored bytes, and become ready only after the server rereads/hashes the saved object and rechecks the exact live actor session/current owner permission. The recovery catalog must include both customer files and owner-network cards, including archived verified photos; pending/unverified files stay excluded from ready-file backups. Native tests must cover the catalog union and permission/retry boundaries.

Referral copy contains only deliberately selected public contact details. Private notes, referral-source notes, vetting evidence and card URLs are excluded. Copy success is checked; no referral is treated as sent and no customer message is sent automatically. Contact methods, business-card images and linked websites do not activate an external AI provider or paid integration.

Entry points: Owner network in the owner’s secondary navigation, plus a referral lookup from the request/job workflow. Preserve existing customer, timer, pricing, scheduling, invoice, tax and communication authority. Required release evidence includes contracts/types/lint, isolated API/UI/database/race tests, private-file byte/recovery tests, role/tenant/revocation cases, phone/desktop light/dark/readability checks, exact-head CI, migration history and read-only deployment verification. Owner/device acceptance and actual vetting remain human evidence.

## Implemented intelligence and phone flow

Owner network appears in the owner/admin secondary navigation. Job and request screens open a native browser dialog with Learn & prepare and Find a referral tools. Opening it preserves the underlying job/request draft and returns focus when closed. Category starting points use explicit inspectable task rules in `owner-support.ts`; they are suggestions, not an LLM or a claim of competence. The owner chooses whom to call or share. The Field guide also links to reviewed task-time reports with the current company ID. Phone search stays visible; secondary filters are collapsed until requested so contacts appear sooner.

Image reads now proxy verified private bytes through the authenticated owner API rather than issuing signed URLs. This rechecks current access on each new read. Up to twelve immutable references, including archived photos, are retained per contact; identical original bytes resume/deduplicate rather than consuming another slot. Archived verified photos remain in recovery coverage. No OCR, automatic message, commercial approval, certification, licensing/insurance validation or paid AI is claimed.
